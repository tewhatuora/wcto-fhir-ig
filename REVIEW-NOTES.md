# Review notes — transcript + WCTO Digital Services draft

This proposed structure:

1. makes the purpose explicit: early vendor planning, indicative estimation and internal alignment, not a final API contract;
2. makes the WCTO Schedule API a central workflow capability;
3. adds Magic Link API and WCTO Summary API as first-class services;
4. adds HPI alongside NHI, NES and AIR;
5. adds authenticated and unauthenticated form-launch models;
6. adds multi-author/staged completion and provenance as core form principles;
7. uses the six-form catalogue from the reviewed draft;
8. adds completed individual forms, Clinical B4SC Summary and Whānau B4SC Summary;
9. removes overly definitive Group/CarePlan/PlanDefinition modelling from the core IG;
10. treats the Schedule workflow resource as unresolved (`Task` or another resource);
11. keeps referral recording separate from unresolved referral-management workflow;
12. adds licensing, version management, corrections and status-model questions to the design backlog; and
13. keeps narrative pages simple Markdown with styling centralised in the local template.
